# 24go.site: разрешённый ежедневный полный цикл

Владелец разрешил автоматическую публикацию проверенных статей на 24go.site. Этот workflow объединяет ДВА раздельных этапа: существующий review-only генератор и разрешённую доставку. Не менять DNS, другие сайты, аккаунты, секреты, конфигурацию или расписания. Не читать .env/auth/credentials. Рабочий каталог /home/hermes-admin/.hermes/skills/statejnik; инструменты /home/hermes-admin/.hermes/scripts.

## 1. Подготовка

Загрузи skills statejnik и statejnik-publishing. Выполни /home/hermes-admin/.hermes/scripts/24go_site_daily_editorial.md как отдельный этап подготовки. Его запрет на публикацию действует ВНУТРИ этапа генерации; не меняй его предохранители. Не более одной новой RU/EN пары за день Asia/Bangkok, pending<=3, реальный inventory/deduplication/research и независимый final_review. Существующий дневной claim означает пропуск создания, но НЕ пропуск проверки уже подготовленной очереди. Не публикуй отклонённое или не принятое редактором.

## 2. Отдельный разрешённый этап доставки

Разрешён только publishing.platforms.24go.enabled=true, auth_mode=local_backend, api_base_url=https://api.24go.site/api/v1/blog и site_url=https://www.24go.site. Отсутствие любого условия — blocker без изменения config. Обрабатывай только scoped RU/EN пары review/review с явными target_site=24go.site, одинаковым slug, locale=ru/en. Уже published не перепубликовывать; смешанные статусы не чинить автоматически. Не включай dev24.pro/24go.asia или стороннюю синдикацию. На один запуск максимум одна пара; сначала самая старая подходящая по created_at.

Для выбранной пары:

Обязательный gate объёма: `python3 /home/hermes-admin/.hermes/skills/statejnik/tools/check_24go_length.py /absolute/work/slug/draft.md`. Каждая локаль отдельно >=7000 символов основного видимого текста по `_article_length.py`, без frontmatter/разметки/рекомендаций; Unicode whitespace схлопывается в один пробел с обрезкой краёв. Сохранить counts/exit code; ошибка — review/blocked. QA packaging, admission, broker и CMS повторяют правило независимо; достаточная длина не является редакционной приёмкой.

1. Вызови `python3 /home/hermes-admin/.hermes/scripts/statejnik_local_cms.py --config /home/hermes-admin/.hermes/skills/statejnik/config.yaml --dry-run /absolute/work/slug/draft.md`. Это настоящий exact-version editorial gate без CMS writes. Ошибка/просроченная приёмка: оставить review, записать blocker; не изготавливать receipts и не подменять модель. При необходимости использовать реальный final_review runner по инструкции генератора, затем повторить gate.
2. Запусти `node /home/hermes-admin/24go-site-deploy/render_review.cjs /absolute/work/slug/draft.md` из /home/hermes-admin/24go-site-deploy. Прочитай `final-review/local-preview/result.json`: обе locale ssr/metadata passed, acceptance/payload/current renderer SHA совпадают. Ошибка — остановка.
3. Выполни НАСТОЯЩИЙ browser_exec для file:// preview ru.html/en.html в local-preview. Через CDP Emulation.setDeviceMetricsOverride проверь mobile 390x844 и desktop 1365x900, deviceScaleFactor=1, mobile=true только mobile. После goto_url и wait_for_load измерь innerWidth, document.documentElement.clientWidth, document.documentElement.scrollWidth, число h1, navigator.userAgent; h1=1, scroll_width<=client_width<=viewport_width. Осмотри скриншоты: читаемость, заголовки, таблицы, код, отсутствие обрезания. Не считать измерения заменой визуального осмотра.
4. Для каждой из четырёх уникальных комбинаций сохрани реальный PNG capture_screenshot в local-preview/screenshots/{locale}-{device}.png и строку в local-preview/browser-cases.json. Поля: locale, device, browser='chromium' (для реального CDP Chromium), url=actual location.href, viewport_width, client_width, scroll_width, h1_count, userAgent, checked_at=actual UTC ISO, acceptance_sha256=result.acceptanceSha256, renderer_sha256=result.rendererSha256, preview_path и screenshot_path относительно final-review, preview_sha256 и screenshot_sha256 от РЕАЛЬНЫХ файлов. Никаких вручную придуманных измерений/картинок или approved:true.
5. Собери evidence: `python3 /home/hermes-admin/.hermes/scripts/statejnik_build_qa_proof.py --renderer '/opt/generator-ad/services/dashboard/src/app/blog/[slug]/page.tsx' /absolute/work/slug/draft.md`. Затем `python3 /home/hermes-admin/.hermes/scripts/statejnik_admit_review.py --config /home/hermes-admin/.hermes/skills/statejnik/config.yaml --dry-run /absolute/work/slug/draft.md`. Только validated и фактически пройденный визуальный осмотр допускают следующий шаг.
6. Допусти ТОЧНУЮ пару: та же команда statejnik_admit_review.py БЕЗ --dry-run. Нельзя вручную ставить draft/published, обходя gate.
7. Доставка: `python3 /home/hermes-admin/.hermes/scripts/statejnik_local_cms.py --config /home/hermes-admin/.hermes/skills/statejnik/config.yaml /absolute/work/slug/draft.md`. Конкурирующий штатный publisher может доставить допущенную пару; в таком случае перечитать статусы и настоящий public readback, а не делать слепой повтор. При неизвестном результате не повторять CMS write в том же запуске и не объявлять успех.
8. После verified независимо прочитай GET https://api.24go.site/api/v1/blog/<slug>?locale=ru|en; сравни title/content/excerpt/meta_description с принятой парой, проверь slug. Открой обе публичные страницы https://www.24go.site/blog/<slug>?locale=ru|en, проверь содержимое, не только HTTP200; Post not found — ошибка. Обе локальные версии должны быть published с одним cms_24go_id и принятым acceptance hash. Только тогда отчёт «опубликовано» с обоими URL.

## 3. Отчёт

Не смешивать успешное завершение агента с доставкой. Если подходящая принятая пара выбрана, но обязательные render/browser/admission/CMS stages завершились ошибкой или blocked, финальный ответ scheduled run должен начинаться отдельной строкой `[CRON_FAILURE]`, затем точный этап и путь к receipt. Hermes распознаёт этот маркер как failure; обычный текст «публикация заблокирована» иначе может оставить last_status=ok. Отсутствие подходящих пар, законный editorial reject или skipped_daily_limit без ожидающей доставки записывать как отдельный честный no-op, не как published и не как транспортную ошибку.

После подтверждённой доставки дополнительно проверить включение ОБОИХ locale URL в актуальный public sitemap и SSR-ссылки на статью в соответствующем архиве. Один раз запустить существующий `python3 /home/hermes-admin/.hermes/scripts/indexing_monitor.py` (у него свой nonblocking lock), прочитать актуальный snapshot `/home/hermes-admin/.hermes/cache/indexing/24go-site/last_status.json` и сохранить discovery/in_sitemap/technical checks в publication receipt. Если lock занят, не создавать параллельный crawler и не считать старый snapshot новым: зафиксировать ожидающую проверку существующим monitor job. Не выполнять массовый Google sweep или создавать дубликат cron.

В отчёте хранить раздельно: editorial_accepted, browser_verified, cms_published, public_body_verified, in_sitemap, archive_linked, indexing_request_submitted, google_indexed. Последние два поля НЕ выводить из HTTP200/exit0/sitemap/inspection API. Без фактического подтверждения UI request indexing поле indexing_request_submitted=false, без свежего Google verdict — google_indexed=UNKNOWN. Авторизация Google/OAuth scope, ручная отправка и синдикация не являются разрешёнными скрытыми side effects этого daily publication job.

Предпросмотр использует действующий renderer через `/home/hermes-admin/24go-site-deploy/render_review.cjs` и production CSS. Парсинг даты сосредоточен в review_preview_runtime.cjs: учитывать кавычки YAML, брать дату только из frontmatter и отклонять отсутствующую/invalid дату. Async RelatedArticles должен быть реально загружен и разрешён до синхронного React18 render с явно пустым preview inventory; это не приёмка реальных рекомендаций. Проверить отсутствие Invalid Date и повторить свежие browser captures после обновления renderer/acceptance. Для технически недоступного browser_exec допустим реальный резервный Chromium runner `/home/hermes-admin/24go-site-deploy/publication-browser.mjs <slug>`; он сохраняет настоящие измерения/PNG/хеши, но не заменяет независимый визуальный осмотр или admission gate.

Сохрани результат запуска с временем, created/skipped, pending counts, independent acceptance, четырьмя реальными browser cases, admission и доставкой. Не переименовывай review_created day-claim в новую попытку; публикация — отдельный checkpoint. Не обещай Google-индексацию: без GSC статус UNKNOWN. При blocker сохраняй точный этап и ненулевой результат/явный blocked; не называй незавершённую публикацию успехом. Отчёт сохраняется локально; доставки сообщения в TUI нет.
