Based on [Google Search Central SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) and related Google documentation.

## 1. Technical Requirements (Must-Have)

Google indexes pages that meet these minimums:
1. **Googlebot is not blocked** — no `noindex` meta tag, no `Disallow` in robots.txt for public pages
2. **Page returns HTTP 200** — no 4xx/5xx errors
3. **Page has indexable content** — text in a supported file type, no spam violations

### Current State (24go.site)
- `robots.txt` ✅ — allows crawling of `/`, `/blog`, `/pricing`, `/features`, `/help`
- `sitemap.xml` ✅ — auto-generated, lists all public pages + blog articles
- `noindex` ✅ — applied to `/dashboard/*`, `/auth/*`, `/admin/*`, `/api/*`
- HTTPS ✅ — enforced via Caddy

### Action Items
- [ ] Verify robots.txt allows Googlebot on all public routes
- [ ] Verify no accidental `noindex` on blog or landing pages
- [ ] Check all public pages return HTTP 200 (no broken routes)

## 2. Sitemap

**What it is:** XML file listing all important URLs with `lastmod`, `changefreq`, `priority`.

**Google's guidance:**
- Include pages you want indexed
- Use `lastmod` to indicate when content changed
- Don't include pages blocked by noindex/robots.txt
- Submit sitemap via Search Console
- Use sitemap index file for >50,000 URLs

### Current State (24go.site)
- `/sitemap.xml` — generated by Next.js
- Includes blog articles, landing pages, pricing, features, help, free tools
- Excludes dashboard, auth, admin, API routes

## 3. Canonical URLs

**What it is:** Tells Google which URL is the "master" version when same content exists at multiple URLs.

**Google's guidance:**
- Every page should have a self-referencing `<link rel="canonical">`
- Use `rel="canonical"` on `<link>` element in `<head>`
- For paginated content, canonical should point to the "view all" or first page
- Don't use noindex + canonical together (confusing)

### Current State (24go.site)
- `app/[locale]/layout.tsx` sets canonical via `generateMetadata`
- Blog articles have self-referencing canonicals

### Action Items
- [ ] Verify every page has a self-referencing canonical
- [ ] Verify canonical URLs use HTTPS and correct domain (`https://24go.site`)
- [ ] For blog paginated pages (`?page=2`), canonical should point to base URL
- [ ] Verify no conflicting noindex + canonical

## 4. Title Tags

**What it is:** The clickable headline in search results. Google uses `<title>` element as primary source.

**Google's guidance:**
- **Unique** per page — not the same title on every page
- **Descriptive** — accurately describes the page content
- **Concise** — ~50-60 characters (Google truncates longer)
- Include brand name (e.g., "24go.site") for recognition
- Include primary keyword naturally

### Current State (24go.site)
- `generateMetadata()` in `app/[locale]/layout.tsx` generates titles
- Pattern: `{pageName} — 24go.site` or localized equivalent

### Action Items

- [ ] Verify titles are 50-60 chars (not truncated in Google)
- [ ] Verify titles include target keywords naturally
- [ ] Blog articles: use `{ArticleTitle} | 24go.site` format
- [ ] Verify title link in Google matches actual `<title>`

## 6. Structured Data (JSON-LD)

**What it is:** Machine-readable markup that helps Google understand content and display rich results (stars, FAQs, how-tos).

**Google's guidance:**
- Use JSON-LD format (recommended)
- Place in `<script type="application/ld+json">` in `<head>` or `<body>`
- Validate with [Rich Results Test](https://search.google.com/test/rich-results)
- Include all required properties for the feature type
- Mark only visible content (don't markup hidden elements)

### Types to Implement for 24go.site

#### a) Organization (Homepage)
```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "24go.site",
  "url": "https://24go.site",
  "logo": "https://24go.site/logo.png",
  "description": "Lead generation SaaS for Telegram and VKontakte",
  "sameAs": [],
  "contactPoint": {
    "@type": "ContactPoint",
    "email": "rf24krsk@gmail.com",
    "contactType": "customer service"
  }
}
```

#### b) WebSite (Homepage — enables Sitelinks search box)
```json
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "name": "24go.site",
  "url": "https://24go.site",
  "potentialAction": {
    "@type": "SearchAction",
    "target": "https://24go.site/blog?q={search_term_string}",
    "query-input": "required name=search_term_string"
  }
}
```

#### c) Article (Blog articles)
```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "{title}",
  "description": "{meta_description}",
  "image": "{og_image_url}",
  "datePublished": "{created_at}",
  "dateModified": "{updated_at}",
  "author": {
    "@type": "Organization",
    "name": "24go.site"
  },
  "publisher": {
    "@type": "Organization",
    "name": "24go.site",
    "logo": {
      "@type": "ImageObject",
      "url": "https://24go.site/logo.png"
    }
  },
  "mainEntityOfPage": {
    "@type": "WebPage",
    "@id": "https://24go.site/blog/{slug}"
  }
}
```

#### d) BreadcrumbList (All pages)
```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    {"@type": "ListItem", "position": 1, "name": "Home", "item": "https://24go.site"},
    {"@type": "ListItem", "position": 2, "name": "Blog", "item": "https://24go.site/blog"},
    {"@type": "ListItem", "position": 3, "name": "{article_title}"}
  ]
}
```

#### e) FAQPage (Help/FAQ pages)
```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "{question_text}",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "{answer_text}"
      }
    }
  ]
}
```

#### f) SoftwareApplication (Landing/pricing page)
```json
{
  "@context": "https://schema.org",
  "@type": "SoftwareApplication",
  "name": "24go.site",
  "applicationCategory": "BusinessApplication",
  "operatingSystem": "Web",
  "offers": {
    "@type": "Offer",

    "priceCurrency": "USD",

  }

```

## 8. Content Quality (Google's People-First Content)

**Google's guidance — "Helpful, reliable, people-first content":**

Ask yourself:
- Does the content provide original information, research, or analysis?
- Does the content provide a complete or comprehensive description?
- Does the content provide insightful analysis beyond the obvious?
- If content draws from other sources, does it avoid simply copying?
- Would you bookmark or share this content?
- Would you read this content in a printed magazine?

**DO:**
- Write for your audience, not search engines
- Make content easy to read — short paragraphs, headings, bullet points
- Update old content — fresh content ranks better
- Use natural language and answer real questions
- Include expert sources where relevant

**DON'T:**
- Keyword stuffing (repeating the same words excessively)
- Scraping or copying content from other sites
- Creating doorway pages (thin pages designed only for SEO)
- Hiding text or links
- Using AI-generated content without human review and value-add

### Action Items for 24go.site Blog
- [ ] Review all 57 articles for "people-first" quality
- [ ] Add original insights, data, or examples to each article
- [ ] Ensure each article answers a specific user question
- [ ] Add "Last updated" dates to articles
- [ ] Cross-link related articles (internal linking)
- [ ] Add author attribution where possible

## 17. Things NOT to Focus On (Google's Explicit Advice)

Google says these things **don't matter** for ranking:

| Myth | Reality |
|------|---------|
| **Meta keywords tag** | Google does NOT use it |
| **Keyword stuffing** | Against spam policies |
| **Keywords in domain/URL path** | Minimal impact, only in breadcrumbs |
| **TLD (.com vs .org)** | Doesn't matter unless targeting a specific country |
| **Minimum content length** | No magical word count target |
| **Subdomains vs subdirectories** | Do what makes business sense |
| **PageRank** | Just one of many ranking signals |
| **Duplicate content "penalty"** | No penalty; Google just picks one URL |
| **Heading order (H1→H2→H3)** | Doesn't matter for Google ranking |
| **E-E-A-T as a ranking factor** | It's not a direct ranking factor |

## 19. Spam Policies (What Gets You Demoted)

Google actively demotes or removes sites that violate spam policies. Know the lines:

### Content Spam
- **Cloaking** — showing different content to Googlebot vs users (violation)
- **Sneaky redirects** — redirecting users to a different page than what Google crawled
- **Keyword stuffing** — unnaturally repeating words to manipulate rankings
- **Hidden text/links** — text invisible to users but crawlable by Google
- **Doorway pages** — low-quality pages created solely to funnel traffic
- **Scraped content** — copying content from other sites without adding value
- **Affiliate pages without value** — thin pages that exist only for affiliate links

### Link Spam
- **Buying/selling links** for ranking purposes (PageRank manipulation)
- **Excessive link exchanges** ("link to me and I'll link to you")
- **Large-scale guest posting** with keyword-rich links
- **Automated link building** via programs or services
- **Links from irrelevant sites** (e.g., link from a casino site to a SaaS)

### Technical Spam
- **Structured data markup** for content not visible on the page
- **Misleading structured data** (e.g., marking non-recipes as recipes)
- **Irrelevant AMP pages** — AMP that doesn't match the canonical page
- **Abusing rich results markup** — marking fake reviews, fake FAQs

### Action Items for 24go.site
- [ ] Ensure structured data matches visible content
- [ ] Don't buy links — focus on organic link building
- [ ] Ensure affiliate/referral links use `rel="sponsored"` or `rel="nofollow"`
- [ ] Don't create thin doorway pages for every keyword variation
- [ ] Blog content must be original, not scraped or AI-only without editorial value

## 20. JavaScript SEO (Critical for Next.js)

Google renders JavaScript, but with limitations. Next.js is generally good because of SSR/SSG, but watch for pitfalls:

### How Google Handles JS
1. **Crawling** — Googlebot fetches the HTML
2. **Rendering** — Googlebot queues JS execution (can be seconds to days)
3. **Indexing** — Google indexes the rendered DOM

### Next.js Best Practices for SEO
- **Use SSR or SSG** — Next.js App Router defaults to server components (good for SEO)
- **Avoid client-side-only rendering** — `useEffect` content is invisible to initial crawl
- **Use `next/dynamic` with `{ ssr: true }` for critical components** — ensures server-rendered
- **Avoid dynamic imports above the fold** — above-the-fold content must be in initial HTML
- **Pre-render dynamic routes** — use `generateStaticParams()` for blog, features, tools
- **Lazy-load below-the-fold JS** — don't block initial render

### Common Pitfalls
- **`'use client'` components** — content renders client-side only; Google can render JS but not always
- **Dynamic content in client components** — lead data, analytics charts won't be in initial HTML
- **Route transitions** — SPA navigation doesn't trigger new page load; Googlebot renders each URL independently
- **Hidden content** — content hidden behind tabs/accordions IS indexed if in DOM, but don't hide critical content

### Action Items for 24go.site
- [ ] Verify all blog content is server-rendered (not client-side)
- [ ] Verify landing page hero text is in initial HTML
- [ ] Test with `curl -A Googlebot https://24go.site/` to see what Googlebot sees
- [ ] Ensure `next/dynamic` components have `ssr: true` for above-the-fold content
- [ ] Verify no critical content only in `useEffect` or `useState`

## 21. Crawlable Links

Google discovers pages through links. If links aren't crawlable, pages won't be indexed.

### Requirements for Crawlable Links
- **Use `<a href="...">` elements** — Google follows `<a>` tags with `href`
- **Don't use JavaScript-only navigation** — `onClick` handlers, `window.location`, React Router `Link` without `href`
- **Don't use non-standard link elements** — `<div onclick="location='...'">` is not a link
- **Avoid link cloaking** — don't show one URL to users and a different URL to Google

### Anchor Text Best Practices
- **Descriptive** — "Telegram lead generation tools" not "click here"
- **Concise** — 5-10 words that describe the linked page
- **Not keyword-stuffed** — natural language

### Internal Linking Strategy for 24go.site
- Blog articles → link to relevant feature pages, pricing, help articles
- Feature pages → link to blog articles, tutorials
- Help pages → link to relevant blog articles and tutorials
- Landing page → link to blog articles (topical authority)

### Action Items for 24go.site
- [ ] Verify all navigation uses `<a href="...">` (not just onClick)
- [ ] Verify React Router links render `<a>` elements (Next.js `Link` does this)
- [ ] Verify anchor text is descriptive, not "click here" or "learn more"
- [ ] Add 3-5 internal links per blog article
- [ ] Add "Related Articles" section to blog posts
